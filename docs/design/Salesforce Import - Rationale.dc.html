Connect. We figure it out. You approve.

A · Recommended UX model

Nine decisions that define the experience

01
Activity is the unit of import, not accounts
Accounts come along because activity points at them. The user never picks accounts — picking 18 accounts is 18 decisions to arrive at the same result the data already implies.
02
One screen carries the whole decision
Counts, destinations, sample records, and exceptions live on a single Review screen. It is a receipt you approve, not a form you complete.
03
Mapping is stated, not configured
The recommendation is written as sentences about outcomes — "94 calls, meetings and emails become account notes" — with the detail one tap behind it.
04
Ambiguity is a queue, not a table
Unrecognized types are asked one at a time, with two real records shown, and three answers: note, action item, or leave out. Two unknowns is two taps.
05
Nothing is written until the user says so
Analysis is read-only and reversible by walking away. That fact is stated on the disclosure and again on Review — it is what makes a light disclosure honest.
06
"Import" is a verb with a date on it
Every surface says when the last import happened. "Sync" never appears anywhere in Lite. The absence of a sync toggle is the clearest way to say there is no sync.
07
Returning imports are a different product
Second import skips disclosure, skips OAuth, reuses saved rules, and shows only what is new since the last run. One tap from Home or Integrations.
08
Success hands off to work, not to a receipt
The success screen shows what was created and drops the user into the account they are most likely to be meeting next, not a generic list.
09
Full integration is mentioned twice, not everywhere
Once in Integrations as a quiet line, once on a stale-import prompt. Never in the flow itself — an upsell mid-import reads as a paywall.
What I would discard from the current screens
"Which field are we filtering on?"
Cut entirely. Halosight already knows which field discriminates best; asking the user to choose between Type, TaskSubtype, CallType, Priority and Status is asking them to debug our query.
Three-way Skip / Note / Task segmented control per value
Cut as the default. Defaulting every value to Skip means the recommendation is "import nothing", and the Import button starts disabled. The system should arrive with an answer.
"STEP 1 OF 2" wizard chrome
Cut. A step counter promises configuration. The default path has no steps to count.
Bare spinner, "Reading your Salesforce records…"
Replaced with a three-beat analysis that names what it found as it finds it. The wait is where the intelligence becomes visible.
"Agree and continue" + consent-panel layout
Softened. Two facts and a plain CTA — "Continue to Salesforce" — reads as trust; a checked/crossed agreement panel reads as a contract.
"Import complete. Imported 2 notes and 1 tasks."
Replaced with created value and a next action. Also fixes the plural bug, which is a small tell that nobody was watching this screen.
"Import from Salesforce" as a flat Profile row
Moved into Data & Connections, where last-import state, rules and the full-integration story can live together. Profile keeps identity and support.
The 60→120 day widening explainer
Kept as a fact, demoted from a paragraph. It becomes a single line under the counts: "Covers activity since Jun 25."
Challenging the brief

Nine questions, answered

Does the user need to understand "mapping" at all?
No. They need to understand consequences. "94 become notes, 29 become action items, 4 left out" is the entire concept. The word mapping never appears in the UI; the entry point is labelled "How activity comes in".
Can Halosight infer and only ask about exceptions?
Yes, for standard Salesforce Type values, which cover the large majority of orgs. Ask only when a value is unseen, or when a value's records split across obviously different shapes.
Should users select accounts?
No. Infer from activity. Provide deselection only inside Review, as a list you can uncheck — used by roughly nobody, but its presence is what makes "18 accounts" feel like a claim rather than a decree.
Does a separate preview screen help?
No — as its own step it is friction. Fold it in: each destination row on Review carries one real example beneath it, and expands to a short list. Confidence without a screen.
Disclosure before OAuth, after, or both?
Before, briefly. Salesforce's own consent screen handles scope; ours handles intent. Repeating it after OAuth implies the first one did not count. Review is the second checkpoint, and it is the one with real numbers.
Where does CRM import belong in the IA?
Home for discovery, Profile → Data & Connections for the durable home. Not in a settings list next to Switch Tenant, and not a top-level tab — it is not a place users visit weekly.
How do we keep import from reading as sync?
Three mechanics: every state is stamped with a date, the CTA is always a verb the user performs, and the connection card shows "Last imported" rather than a status light. Never a green "Connected" pill.
How does success lead to value?
By naming a next meeting. "Jack's Tire & Oil now has 9 notes — you visited 2 weeks ago" beats "View my accounts", because it points at the thing the rep was going to do anyway.
Minimum decisions before import?
One: approve. Plus one per unrecognized activity type. A clean org goes Home → Continue → Salesforce → Import, with a single deliberate tap on each of four screens.

E · Authentication disclosure

The screen before OAuth, word for word

Salesforce's own consent screen covers scope. This screen covers intent, which is the part the user actually can't infer. It earns trust by being short and by naming the limits without a checkbox.

Final copy
Title
Before we connect
Subhead
You'll sign in to Salesforce next. Here's exactly what Halosight does with what it finds.
We look at
Your Salesforce tasks and activity from the last 60 days
The accounts that activity is attached to
Your Salesforce name and email, to file it under you
We copy, once
Those accounts, as companies in Halosight
The activity, as account notes or action items
Boundary card
A one-time copy, not a sync.
Halosight won't change anything in Salesforce, won't read a colleague's records, and won't check back on its own. You import again whenever you want to.
Expandable · "What gets imported?"
Halosight reads your recent tasks, groups them by the account each one is attached to, and turns them into account notes or action items. Activity with no account attached is left behind. If fewer than 100 records turn up, we widen the window to 120 days.
Footnote above CTA
You'll see what we found, and approve it, before anything is copied.
Primary CTA
Continue to Salesforce
Why two lists instead of three
The current concept splits into "what we read" and a four-item "what we never do" list. Four negations read as defensiveness. Compressing them into one sentence inside a boundary card keeps every fact and removes the courtroom tone.
Why not "Agree and continue"
Nothing is being agreed to. The user is being told what happens next, and the real consent moment is the Import button, which has counts attached. "Agree" borrows weight from legal flows and spends the user's caution in the wrong place.
Why no Cancel button
The close affordance in the header is the cancel. A full-width Cancel next to the primary CTA implies the choice is risky enough to need a matched pair.
Second and later imports
This screen does not reappear. It returns only if the user connects a different Salesforce account, or if scopes change — the two cases where the facts genuinely differ.
G · States and edge cases

Eighteen cases, five behaviors

Grouped by how the UI responds, not by cause. Only two groups get a screen of their own; the rest resolve inline.

Group 1 · One screen, cause-specific line
Connection didn't complete
Auth failure · expired session · insufficient permissions · different Salesforce account · scopes revoked
A single screen with a fixed shape: title, one sentence naming the cause in the user's terms, one primary action. The shape never changes, so the user learns it once.
Auth failed
"Salesforce didn't finish signing you in. Nothing was imported." → Try again
Session expired
"Your Salesforce session has expired. Sign in again to pick up where you left off." → Sign in to Salesforce
Missing permissions
"Your Salesforce account can't read tasks and activities. Your Salesforce admin can turn that on." → Copy details for your admin
Different account
"This is a different Salesforce account than last time. Anything already imported stays put." → Continue / Use the other account
Cancelled OAuth is deliberately not in this group — a user who taps Deny gets returned silently to where they started, with no error and no modal. Cancelling is not a failure.
Group 2 · One screen, honest dead end
Nothing worth importing
No activity found · every task has no AccountId · zero accounts qualify · all accounts inaccessible
All four have the same consequence, so they share a screen and differ only in the explanatory line. Crucially it offers the manual path rather than leaving the user at a wall.
Nothing to import yet
We looked at your Salesforce activity from the last 120 days and didn't find anything attached to an account. Halosight can only bring across activity that's linked to a company.
Variant, tasks exist but are unlinked: "We found 22 tasks, but none of them are attached to an account in Salesforce, so there's nothing to file them under."

Group 3 · Resolved inline on Review
The data is odd, not broken
Unknown types · low confidence · some tasks unlinked · inaccessible accounts · duplicates · already-imported records · everything set to Leave out · saved rule no longer valid
None of these deserve a screen. Each becomes a line on the Review screen that the user can act on or ignore.
Unknown / low confidence. Amber row: "2 activity types need your call." Tapping opens one question per type. Import stays disabled until answered — the only time it ever is.
Unlinked or inaccessible. Folded into the "Left out" row: "4 · No account attached in Salesforce", with "2 in accounts you don't have access to" beneath when relevant.
Duplicates / already imported. Deduped by Salesforce record id before Review, so the counts are already net-new. One line states it: "31 you've already imported are skipped."
Everything left out. Import button reads "Nothing selected to import" and is inert; the Left-out row is expanded automatically so the cause is visible rather than deduced.
Existing account matched. "3 of these are companies you already have — we'll add the activity to them." Merge, never duplicate, matched on Salesforce account id first and name second.
Saved rule went stale. Rules for values that no longer exist are dropped silently. New values arrive as the amber row — the same mechanic as first run, which is why it needs no extra design.
Group 4 · Progress, not blocking
It's taking a while
Slow Salesforce API · hundreds of records · user leaves mid-import · partial failure
The import runs server-side, so the UI is a window onto it rather than a lock. Accounts are written first, which means the app is usable within seconds even on a large import.
Any size. Phase labels, not percentages of a mystery: "Adding 18 accounts" → "Writing 94 account notes" → "Creating 29 action items". Over 300 records, add "This one's large — around two minutes."
Leaves the app. Import continues. A local notification on completion: "Salesforce import finished — 18 companies are ready." Returning mid-run reopens the progress state from the server.
Slow API. After 20 seconds: "Salesforce is being slow. This keeps running even if you close the app." Never a timeout that discards work.
Partial failure. Still the success screen — most of it worked. One amber row: "6 activities didn't come through" with Retry those 6. Retrying is idempotent.
Group 5 · Reversal
Undo an import
User wants imported data gone · wrong Salesforce account · regret after seeing the result
Every import gets a record in Data & Connections → Import history, and each entry can be removed. Scope is stated precisely, because the honest version of undo has an exception.
Remove this import?
This deletes the 94 notes and 29 action items from the Aug 24 import. Companies stay, and so does anything you've written or changed yourself since. Nothing in Salesforce is affected.
Remove importKeep it
Edited items are preserved and reported: "3 notes you've edited were kept." Deleting a rep's own writing to satisfy a tidy undo is the worse failure.

Open questions for you
Can mapping rules actually persist per user in Lite today, or does every import start from the recommendation? The returning-import design depends on it.
Is the 60-day window a product decision or an API constraint? If it's a decision, "since Jun 25" should be adjustable later.
Can the import run server-side after the app is closed? Group 4 assumes yes; if not, the progress screen has to hold the user and the copy changes.
Is per-import removal feasible on the current data model? Without it, the honest answer to "undo" is "delete the companies", which is worse.
